# Security Policy

## Scope and current restrictions

This project is an early-stage prototype. It is not approved to store or process real community, customary, cultural, biological, legal-claim or sensitive personal information.

**Do not submit sensitive information through public GitHub issues, pull requests, commits or discussions.** Use synthetic examples only.

## Reporting a vulnerability

Do not publish exploitable vulnerability details in a public issue. Contact the repository owner privately through GitHub's available security reporting channel, if enabled. Until a private reporting channel is configured, do not include sensitive exploit details in this public repository.

## Security principles

- Deny access by default; enforce authorisation server-side.
- Apply least privilege and workspace isolation.
- Keep secrets out of source control and client bundles.
- Use private storage for files; never expose private object URLs publicly.
- Log security-relevant actions without copying sensitive record contents into logs.
- Treat external services, AI providers, backups and legal demands as part of the threat model.
- A UI disclaimer is not a substitute for technical access controls.

## Readiness status

No security certification, penetration test, privacy assessment or production approval has been completed. No real-data pilot is authorised.
